# Combat Effect Audit

**Date:** 2026-10-18
**Branch inspected:** `feature/castle-management-first-pass`
**Scope:** Read-only inventory of the combat effects and behavior named in the Step 4 request, checked against the current perk catalog, combat logic, tests, and AP/Martial Techniques roadmap. No tests were run for this audit.

## Evidence key

- **Verified** means directly present in the inspected source or test.
- **Inference** means a likely interpretation based on current action definitions, not an explicit design rule.
- **Unresolved** means existing source and design material do not settle the intended behavior sufficiently for a safe gameplay change.

## Recommended next implementation task

**Correct only the Speed Rush description in `frontend/src/game/perks.js` to match the existing five-second, 1.5× movement-speed effect.** Evidence: `useHeroAbility` sets the five-second deadline and `engine.js:update` applies the 1.5× factor to movement; no attack tempo multiplier is applied. The roadmap explicitly records that this description must match actual movement/tempo behavior (`AP_PERK_TREE_AND_MARTIAL_TECHNIQUES_IMPLEMENTATION_ROADMAP.md`, P1 items). A description-only correction preserves combat behavior and does not require a new mechanic.

## Explicitly deferred decisions

Do not implement the other listed effects based on this inventory alone. Their unresolved target, trigger, ordering, duration, stacking, or policy rules are listed above. Rogue Combo specifically remains deferred: the approved eligible-action scope does not define how “successive strikes” start, continue, or reset. Existing baselines such as reactive support priority and native area abilities must not be altered merely to make dormant perk flags appear effective.
